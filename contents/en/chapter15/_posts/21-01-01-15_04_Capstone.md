**Teams:** exactly **two** students (an instructor may allow a singleton only with written reason).  
**Length:** a short report, not a product company.  
**Cloud:** optional. A localhost Compose + plan-only IaC submission is complete.  
**Integrity:** original IUH brief. Do **not** paste text from [infracourse.cloud](https://infracourse.cloud/) or any other university’s assignment.

The same brief lives in the repository as [`PROJECT.md`](https://github.com/nglelinh/service-oriented-architecture-and-cloud-computing-iuh/blob/main/PROJECT.md) for people who clone the notes.

## Purpose

Show that you can **design and operate** a small multilayer service with the Deploy Track vocabulary: tiers, least-privilege network, an elasticity story, a security baseline, a name-and-TLS story, and a cost paragraph. Spark and Hadoop are out of scope unless you use them as an optional backend.

## The product (IUH Course Board)

Build a **course help board** for one fictional faculty:

- Visitors can **list** and **create** posts (course code, title, body, created-at).
- Optional stretch: tag a post as “resolved,” or a tiny search box.
- **Forbidden:** real student names, MSSV, grades, or exported LMS data. Use synthetic fixtures.

You may use any language the pair already knows. The grade (if any) is the **operations story**, not the framework fashion.

## Required architecture (multilayer)

At least **three** runtime roles:

1. **Edge** — HTTP(S) entry (reverse proxy or managed frontend).
2. **Application** — stateless API if you can; document it if you cannot.
3. **Data** — PostgreSQL, MySQL, or Redis *plus* a persistence story (volume or managed DB).

Draw these roles on one diagram. Arrows must match the security group / Compose network story from Lab A and 01-07.

## Required themes (write each as a subsection)

### 1. Infrastructure as Code

- Check in HCL (or a CDK/Pulumi *concept* appendix if you truly used one—Chapter 14 compare).
- Default: **OpenTofu/Terraform plan** for either the Docker provider (local) or a cloud network you were allowed to touch.
- If you clicked in a console, add a “ClickOps debt” paragraph and what you would move to code next.

### 2. Elasticity

Pick **one** honest mechanism and demo it:

- Compose `--scale` / two API replicas behind the edge, **or**
- A Kubernetes Deployment `replicas: 2` on a local kind/minikube (if you already have Chapter 09), **or**
- A managed scale-to-zero service (only with Lab C hygiene).

Write what happens when load is **zero** and when you **kill one replica**.

### 3. Security baseline

Minimum:

- Datastore not published on the campus LAN.
- Secrets not in Git; rotate if they leaked.
- Dependency pin or lockfile.
- A two-row threat note: (a) leaked `.env`, (b) public database port.

IAM on a public cloud is required only if you used a cloud. Then: least-privilege deploy role, no `*:*` screenshots as a joke.

### 4. DNS and TLS

Choose a **lane** and mark it:

| Lane | Acceptable evidence |
| --- | --- |
| Local | `mkcert` or documented HTTP-only localhost + a paragraph on what a real name/cert would be |
| Public hello | HTTPS URL + who issued the cert + TTL of the DNS record |

“We used an IP in the browser bar” needs an explicit limitation note.

### 5. Observe and deliver

- `/healthz` plus one RED or structured-log screenshot during a **forced failure**.
- A CI workflow *or* a documented `make test` that a clean machine can run (Chapter 13-04).
- Rollback: previous image digest or `git` tag. Two sentences.

### 6. Cost

Even if spend is zero: fill the [12-03 checklist]({{ site.baseurl }}{% multilang_post_url contents/chapter12/21-01-01-12_03_FinOps_Billing_Literacy %}) in abbreviated form (unit of work, idle cost, destroy owner). If you used cloud, attach a dated billing screenshot.

## Deliverables

Submit a **single PDF or Markdown report** (about 4–8 pages) plus a **link to a Git repository** both members can access:

1. Title, pair names, student IDs, date.
2. Architecture diagram (one page).
3. The six theme subsections.
4. How to run locally (`make up` or equivalent).
5. What you would do with one more week (honest).
6. Statement: “We did not copy another university’s assignment text.”

Optional demo video ≤ 5 minutes. Live demo if the instructor schedules it.

## Suggested split of work (pairs)

Do **not** split “I write code / you write the report.” Split **vertical slices**:

- Partner A: edge + TLS/DNS lane + health on the public path.
- Partner B: API + datastore + Compose/IaC + destroy.

Both must be able to run `up` and explain the diagram. The instructor may ask either person any section.

## Timebox

A serious pair can finish from Lab A notes in about **two weeks** of part-time work. Cut features, not the six themes.

## What “done” is not

- A notebook that calls a managed LLM API and no datastore.
- A single container that bind-mounts `/`.
- A Kubernetes YAML you cannot apply locally and did not plan in Lab B.
- A report that only restates lecture headings.
